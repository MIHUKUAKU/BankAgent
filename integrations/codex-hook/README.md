# Codex 原桌面联系路线 Hook

复用 [官方 Hooks](https://learn.chatgpt.com/docs/hooks)，保持桌面拥有原聊天和原生搜索、执行工具。仅自写固定收件路线到 PreToolUse 协议的适配，不启动外部聊天宿主。

## 安装

1. 将 routes.example.json 复制为同目录 routes.json，将所有占位符替换为自己的真实聊天 ID，按角色配置 routes。该文件不要提交到公开仓库。
2. 将 hooks.example.json 合并到项目 `.codex/hooks.json`；command 中填入实际 Python 和 route_hook.py 的绝对路径。不要覆盖已有 Hook。
3. 按当前 Codex 官方文档启用 Hooks 并审核信任该定义；改变定义后可能需要重新信任。原安装使用 Codex 0.166.0-alpha.5.1，其他版本未逐一验证。
4. 在自己的正式正常任务中检查实际事件；用户直接输入不经过这条自动发送规则。

当前模板展示总控、执行、审核、市场四角色；可按同样方式扩展固定角色。公开模板不会自动绑定真实人员。

## 已实现

从宿主提供的 session_id 识别发送方，读取 threadId，按 routes.json 判断自动发送目标；只记录调用 ID、双方标识、决定及消息哈希，不记录消息全文。已知角色的未允许路线返回官方 deny。项目外未知角色不在本适配范围内。允许路线不替代发送工具原本的人类授权规则。

## 已验证与限制

原项目用户确认一个聊天直接输入回复；市场角色真实完成来源读取、保存、回报，实际发送经过 Hook 并获得允许。公开包不附私人运行日志，以上是实际部署的结果摘要，不是读者环境的自动证明。

这是流程约束，不是完整安全边界：部分工具路径不经过 Hook，宿主错误或超时策略也可能继续调用。它不隔离文件、网络、凭据或进程，不实现任务状态鉴权，不替代候选审核发布门禁。其他旧活动回合的配置加载没有逐一验证，专项市场争议临时路线需正式登记。上述结果仅代表已完成的正常功能场景。

## 停止与回退

在官方 Hook 设置禁用本项目定义，或移除自己新增的该项配置；不要删除其他项目 Hook。不要同时运行持有同一聊天写入权的外部宿主。
