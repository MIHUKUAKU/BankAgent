# 年报发布后的核心表格

企业执行员在每次研究、资料更新时检查本企业官方年报披露。发现新年报后，将年报阅读和核心表格提取列为必做任务。每份年报独立保存来源及压缩包，不以压缩代替原文保存。不宣称已部署实时监测。

默认五张表，可按企业实际合并或拆分为四至六张：
1. 业务与收入结构：主营业务、产品/服务、客户类型、分部收入及利润、地区与海外收入、集团财资安排；未披露明确留空。
2. 利润与现金流：收入、成本、利润、经营/投资/筹资现金流、资本开支与分红。保留本期及可比上期，计算指标附公式和输入引用。
3. 资产负债与营运资金：现金、应收、存货、应付、资产、负债、权益；注明时点及受限资金，计算周转指标须有完整口径。
4. 投资与融资：债务期限、币种、利率结构、融资工具、重大投资/资本开支、担保及承诺；集团与母公司、存量与流量分开。
5. 主要风险与银行业务线索：年报披露的汇率、利率、流动性及集中度风险，映射可能的结算、现金管理、融资或避险需求。原文事实与需求假设分栏，不把假设写成真实需求。

每条数据保留company_id、报告名称/报告期、实际披露日、来源URL、PDF SHA-256、PDF物理页码与印刷页码/表名、主体口径、单位、币种、原始数值/文字及审核状态。不同财年、会计准则、期间不得直接混比；重述值注明，未知项不填造。

默认交付 cases/<company_id>/annual-report-tables/<report_id>/ 下 tables.vN.md（便于阅读的核心表）、tables.vN.json（同源结构化记录）、source_manifest.vN.json 和 task_result.vN.json。原文沿用本企业不可变来源目录。更正追加版本，原件及旧版本保留。

先形成候选，由本企固定审核员核对数字、口径、来源定位、跨表勾稽及完整性，审核绑定确切hash；审核与发布分离，固定审核员通过受控接口追加本企业RAG。压缩表不得自行获得“已核实”状态。已审核旧数据可按确切版本引用，不重复业务审核；新提取/新汇总仍核对转换准确性。

历史月报只能引用截止前已披露的年报；当前年报补全与历史模拟分开保存。已送审原件保持hash稳定，需要增补时另起版本，不能静默覆盖。


审核失败直接退作者修订，通过按[发布与记账](reviewer-publication-ledger.md)完成并通知总控。
