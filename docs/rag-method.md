# RAG 方法：公开机制，不公开真实知识库

本项目的 RAG 是来源可追溯的知识管理与检索层。当前核心使用 SQLite 与 FTS5 词法检索，不宣称已实现向量数据库、语义重排或完全自动的生成流水线。

## 数据组织

知识分为 finance、products、enterprises、engineering。企业事实同时绑定 company_id、报告期、公开时间、单位、资料定位和版本。事实、估计、情景假设与缺失值分别标记，避免将估计当作披露数据。

示意记录如下，仅说明方法，不是可直接导入的正式 schema，也不是任何企业真实数据：

```json
{
  "domain": "enterprises",
  "company_id": "fictional_company",
  "record_type": "fixture",
  "period": "2025",
  "metric": "revenue",
  "value": 100,
  "unit": "fictional_unit",
  "source": {"url": "https://example.com/fictional-report", "location": "示例表1"},
  "verified": false
}
```

具体输入结构以各 CLI 子命令 `--help` 和 finance.py、enterprises.py 等模块校验规则为准。

## 从资料到可检索知识

1. 收集适用时点之前的原始公开资料，记录发布日、访问日、URL、页码或表格定位；本地保留原件及哈希。
2. 解析正文和表格，保留原始单位、币种和报告期。年报压缩为核心经营、财务、现金流、融资与风险表，表格仍指向原文。
3. 将事实与推断分开，形成候选知识包。缺失值按有依据的行业均值、可比企业或明确假设估计，保留方法及区间。
4. 固定审核员检查确切候选及来源。失败直接退修；作者不能自审。审核记录绑定候选摘要，防止审核后内容悄然变化。
5. 经受控接口追加新版本并写发布账本；历史版本不可覆盖。纠错追加新版本，而不是改掉旧记录。
6. 查询时先应用知识域、company_id 和版本等访问条件，再进行词法匹配，返回内容及来源上下文。生成报告时引用原始资料，不把“来自 RAG”当公开来源。

## 权限与可追溯性

核心能力检查依赖可信宿主创建角色；直接拥有数据库文件权限的人仍可能绕过业务接口。需要强制多租户隔离时，应另外使用服务端身份认证、独立存储权限和受控执行环境。聊天 Hook 不替代数据库授权。

## 本仓库公开与保留范围

公开：数据组织方法、状态流转、检索代码、Skill、明确标记的模拟演示。

不公开：实际 SQLite 数据库、企业事实包、审核原始档案、账号与聊天 ID、第三方资料全文和下载缓存。使用者须自行取得来源、建立本地知识库并完成审核。随附 PDF 是研究展示，不代表真实 RAG 可由仓库完整还原。

## 待改善
